Lesson 0005 • Production & Deployment

ขั้นตอนการ Deploy และเจาะลึกโฟลเดอร์ dist
ทำความเข้าใจกระบวนการแปลงโค้ดจากเครื่องช่างไปสู่การเปิดให้บริการจริงในโรงพยาบาล

บทก่อนหน้า: 0004: scripts/ กับ public/

1. โฟลเดอร์ dist/ คืออะไร? (The Distribution Artifact)

คำว่า `dist` ย่อมาจาก Distribution แปลว่า "กล่องสินค้าสำเร็จรูปที่พร้อมแจกจ่าย/ส่งมอบ"

🏥 อุปมาเปรียบเทียบ: ซอร์สโค้ดใน src/ เหมือนกับ "วัตถุดิบและสูตรยาในห้องทดลอง" (คนไข้กินไม่ได้ ต้องผ่านกรรมวิธีผลิตก่อน)

โฟลเดอร์ dist/ คือ "ยาเม็ดที่ผ่านการสกัด บรรจุแผง ใส่กล่อง ปิดฉลากเรียบร้อยแล้ว" พร้อมนำไปวางที่ชั้นจ่ายยาของโรงพยาบาลให้คนไข้เปิดใช้งานได้ทันที

2. สายพานการผลิต 4 ขั้นตอนของ npm run build

เมื่อเราสั่ง npm run build ใน package.json ระบบจะรัน 4 ขั้นตอนต่อเนื่องกันอัตโนมัติ:

1. clean-build.mjs

ล้างสต็อกเก่า ลบโฟลเดอร์ dist/ และ out/ เดิมทิ้ง เพื่อป้องกันไม่ให้มีไฟล์ค้างเก่าปะปนกับของใหม่

2. write-runtime-config.mjs

อ่านค่า .env มาสร้างเป็นไฟล์ runtime-config.js เพื่อเตรียมพร้อมสำหรับส่งมอบ

3. next build

อบโค้ด React/TypeScript ทั้งหมด กลั่นกรองออกมาเป็นไฟล์ HTML, CSS, JavaScript ที่ผ่านการบีบอัดจนมีขนาดเล็กที่สุด

4. publish-export.mjs

จัดรูปแบบโครงสร้างโฟลเดอร์ dist/ และ dist/patient/ พร้อมใส่สคริปต์ Redirect อัตโนมัติ

3. ผ่าชิ้นส่วนข้างในโฟลเดอร์ dist/ แต่ละไฟล์คืออะไร?

ไฟล์ / โฟลเดอร์ มันคืออะไร? หน้าที่ของมัน
index.html โครงสร้างหน้าเว็บหลัก หน้าจอแรกที่เปิดขึ้นมาตอนคนไข้สแกน QR Code เข้ามาที่เว็บโรงพยาบาล
runtime-config.js ป้ายบอกทาง API ไฟล์ข้อความที่ระบุว่า API ของ รพ. อยู่ที่ URL ไหน (แก้ไฟล์นี้ได้โดยไม่ต้อง build ใหม่)
_next/static/ ไส้ในและกลไกทั้งหมด ก้อนไฟล์ JavaScript และ CSS ทั้งหมดที่ถูกบีบอัด รวมโค้ดปุ่ม ฟอร์ม และเสียงกระดิ่งคิว
patient/ โฟลเดอร์จำลองเส้นทาง รองรับ basePath: /patient ทำให้เว็บเปิดได้สมบูรณ์ทั้งแบบมีหรือไม่มี /patient
404.html หน้าแจ้งเตือนหาไม่เจอ แสดงผลเวลาคนไข้พิมพ์ URL ผิด

4. ขั้นตอนการ Deploy สู่เซิร์ฟเวอร์จริงของโรงพยาบาล

เนื่องจากเป็น Static Export การ Deploy จึงง่ายและปลอดภัยอย่างยิ่ง:

  1. Step 1: สั่ง Build รัน npm run build บนคอมพิวเตอร์ หรือให้ GitHub Actions รัน
  2. Step 2: อัปโหลดโฟลเดอร์ dist คัดลอกเฉพาะสิ่งที่อยู่ในโฟลเดอร์ dist/ ไปวางไว้บน Web Server ของโรงพยาบาล (เช่น Nginx, Apache หรือ Cloudflare Pages) โดยไม่ต้องลง Node.js บนเซิร์ฟเวอร์เลย!
  3. Step 3: ตรวจสอบ runtime-config.js ตรวจสอบว่าในไฟล์ runtime-config.js บนเซิร์ฟเวอร์ ชี้ไปที่ https://hospital.bfirstkok.me เรียบร้อยดี
  4. Step 4: เปิดให้บริการ คนไข้เปิดมือถือ สแกน QR Code หน้าตึก OPD ใช้งานระบบคิวได้ทันที!
🧠 ทดสอบความเข้าใจ: ทำไมบนเซิร์ฟเวอร์จริงถึงไม่ต้องติดตั้ง Node.js?

ทำไมเวลาเรานำโฟลเดอร์ dist ไปขึ้นเซิร์ฟเวอร์โรงพยาบาลจริง เราถึงไม่จำเป็นต้องติดตั้ง Node.js หรือรันคำสั่ง npm อีกต่อไป?
